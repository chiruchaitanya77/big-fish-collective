# Big Fish Collective editable website

This is the complete editable source export of Big Fish Collective, version 17, dated 8 October 2026. It includes all ten pages, the current logo and images, styling, form handling, analytics, database migrations, tests and a production build. Start here to edit your own copy.

The application runs on Cloudflare Workers with a D1 database, using React, TypeScript, Tailwind and Vinext (Next-compatible APIs). It is a code project; it is not a WordPress theme or a drag-and-drop website-builder template. Editing this copy does not change the existing published ChatGPT Site.

## Open and edit

1. Extract the ZIP into a normal folder, such as `Documents/big-fish-collective`. Do not edit files while they are still inside the ZIP.
2. Open the extracted `big-fish-collective` folder in your code editor, such as Visual Studio Code.
3. Install Node.js 24. Open a new terminal in that folder and run:

```sh
npm install -g pnpm@11.25.0
pnpm install --frozen-lockfile
pnpm run db:local
pnpm run dev
```

Open the localhost address printed in the terminal (normally `http://localhost:5173`). Keep the terminal running. Save an edited source file to refresh the development preview. Stop the server with Ctrl+C.

The dependency folder is intentionally not included; installation downloads the exact versions from `pnpm-lock.yaml`. Internet access is required. These commands are suitable for Windows PowerShell, macOS Terminal and Linux. This independent export needs no Sites plugin to edit, build or deploy.

## Host independently on Cloudflare

This application needs a Worker runtime and a D1 database. Uploading this folder to cPanel `public_html`, GitHub Pages, or a basic static host will not run its enquiry forms. A Vercel or Supabase deployment requires adapting the runtime and database code; it is not configured in this export.

1. Sign into your own Cloudflare account and create your own database:

```sh
pnpm exec wrangler login
pnpm exec wrangler d1 create big-fish-collective-enquiries
```

2. Open `wrangler.hosting.json`. Replace the placeholder `database_id` with the ID returned by Cloudflare. Keep the binding name `DB`. Choose a unique Worker `name` if needed. Do not edit the generated `dist/server/wrangler.json` for production; builds overwrite it.
3. Build, apply migrations to the new database, check the deployment and publish:

```sh
pnpm run build
pnpm run db:remote
pnpm run hosting:check
pnpm run hosting:deploy
```

The last command publishes to your account and prints the URL. Add a custom domain through Cloudflare Workers settings when ready. Cloudflare account limits and billing apply. The migration command creates tables in your selected database; it does not copy records from the existing hosted Site. Use the same sequence after changes; applied SQL migrations are tracked and are not replayed.

The export's original Site identity has been removed. Your independent deployment is a separate public site with its own database and configuration. The current website remains unchanged.

## Enable enquiry emails

The forms store enquiries even when email is not configured. To activate notifications, verify a sending domain in Resend and configure these production secrets using your confirmed addresses:

```sh
pnpm exec wrangler secret put RESEND_API_KEY --config wrangler.hosting.json
pnpm exec wrangler secret put ENQUIRY_FROM_EMAIL --config wrangler.hosting.json
pnpm exec wrangler secret put ENQUIRY_TO_EMAIL --config wrangler.hosting.json
```

Each command prompts for the value; do not paste actual secrets into source files or Git. Set FROM to a verified Resend sender and TO to your receiving inbox. Configure these after the initial Worker deployment. `wrangler secret put` applies a new deployed version.

For optional Google Analytics:

```sh
pnpm exec wrangler secret put GA_MEASUREMENT_ID --config wrangler.hosting.json
```

Enter your `G-...` measurement ID. Basic first-party aggregate analytics already works with D1 after visitor consent. No Resend credentials or Google property are included. Read `docs/technical-requirements.md` for implementation details and remaining optional integrations. Its Sites deployment notes describe the original website; use the commands in this README for this independent copy.

## Admin dashboard

The private dashboard is available at `/admin`. It shows consented, aggregate visitor traffic, unique visitors, returning visitors, call-to-action signals, form conversions, top pages, and the latest enquiries. No individual visitor profiles or enquiry contents are sent to the analytics views. After analytics consent, the site stores a random first-party `bfc_visitor_id` cookie for up to one year; it is not a device fingerprint. Only a SHA-256 hash is stored in D1, and declining analytics removes the cookie.

Clicking an enquiry opens the complete submitted brief/application in a drawer. Enquiry status is intentionally one-way: `Received → Responded → Closed`. Each move requires reviewing and confirming the exact email template, sends that email to the person who submitted the form, and records the transition in the enquiry timeline. If email delivery is unavailable, the status remains unchanged so the team does not appear to have responded when no message was sent.

Before deploying, add the initial core-developer account as encrypted Cloudflare Worker secrets. These commands target the database/Worker configuration in [`wrangler.hosting.json`](./wrangler.hosting.json); they prompt you for the values, so the password is never written into that file:

```sh
pnpm exec wrangler secret put SUPER_ADMIN_EMAIL --config wrangler.hosting.json
pnpm exec wrangler secret put SUPER_ADMIN_PASSWORD --config wrangler.hosting.json
```

When prompted, enter the core developer email and a unique password of at least 16 characters. Then apply the database migration and deploy the Worker:

```sh
pnpm run db:remote
pnpm run hosting:deploy
```

The first successful login seeds that account as the super admin. Super admins can create additional admin and super-admin accounts, suspend access, change roles, and review each account's last sign-in. Passwords are salted and PBKDF2-hashed; the browser receives only a `Secure`, `HttpOnly`, same-site session cookie that lasts for 14 days or until the account is suspended or signs out. Do not add these values to `wrangler.hosting.json`, `.env` committed files, Git, or the public folder. Once the initial account has been seeded, the bootstrap secrets can be removed from the Worker; the stored account remains available.

For local development only, put the same values in an ignored `.dev.vars` file beside the project root (not in `wrangler.hosting.json`):

```dotenv
SUPER_ADMIN_EMAIL=core-developer@example.com
SUPER_ADMIN_PASSWORD=replace-with-a-unique-16-character-password
```

Never add `.dev.vars` to the ZIP, a Git repository, or the public folder.

## Database files and backups

`drizzle/` contains the ordered SQL migrations needed to recreate the database structure, including enquiries, rate limits and analytics counters. This export is a source-code dump and schema backup, not a live-data dump. No submitted enquiries, analytics records, account credentials, production database credentials or API keys are included.

Manage production records through your authorized Cloudflare dashboard. Before future schema changes, back up the database and test the new migration locally. Edit `db/schema.ts`, run `pnpm run db:generate`, inspect the new SQL, then run the local migration command. Do not rewrite already-applied migrations.
